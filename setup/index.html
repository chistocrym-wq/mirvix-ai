Что нужно подключить

Все ключи и пароли вносятся только в интерфейс Netlify/Supabase. Не отправляйте секретные данные в чат, письма, GitHub и публичные формы.

Сейчас в репозитории существуют готовые адаптеры SerpApi и семи ИИ, но само наличие кода не подтверждает ключи, баланс и доступность поиска. Я могу видеть код, но не значения или наличие ваших секретов в Netlify. Статус «Работает» устанавливается только после реального одиночного теста и сохранения результата.

1. Supabase — обязательный новый компонент

  1. Откройте Supabase Dashboard. Создайте один проект MIRVIX AI, если подходящего ещё нет. Выберите регион размещения с учётом требований обработки персональных данных ваших клиентов.
  2. В проекте откройте SQL Editor. Последовательно примените миграции 001 и 002 из GitHub. Сначала проверьте их на тестовом проекте, затем — на рабочем. Убедитесь, что у каждой таблицы включён RLS.
  3. Откройте Project Settings → API. В Netlify добавьте SUPABASE_URL (Project URL), SUPABASE_ANON_KEY (публичный anon/publishable ключ) и SUPABASE_SERVICE_ROLE_KEY (строго секретный service_role). Значение service_role доступно только серверным функциям — никогда не размещайте его в HTML или JavaScript.
  4. В Authentication → URL Configuration добавьте адреса возврата: https://deploy-preview-38--resonant-cupcake-231bab.netlify.app/platform/, https://deploy-preview-38--resonant-cupcake-231bab.netlify.app/connections/. После публикации понадобится добавить маршруты основного домена.
  5. В Authentication → Providers → Email включите email-вход и проверьте доставку письма. При реальном запуске настройте собственный SMTP с лимитами и защитой от злоупотребления.
  6. Создайте первоначальную учётную запись администратора в Supabase Auth. В SQL Editor назначьте её по UUID: insert into public.platform_staff(user_id,role) values ('UUID-ПОЛЬЗОВАТЕЛЯ','admin') on conflict(user_id) do update set role='admin';. Не назначайте администратора по email непосредственно в пользовательском интерфейсе.
  7. Откройте кабинет и войдите по ссылке на email. После этого создавайте организации, проекты и отправляйте индивидуальные приглашения сотрудникам и клиентам.

Supabase предлагает бесплатный тариф с лимитами. Платный тариф может понадобиться при росте БД, авторизации, хранения и трафика. Проверьте условия на Supabase Pricing.

4. Конкурентные запросы — какой сервис выбрать

Для MIRVIX AI требуется два разных исследования: обратная семантика доменов в Яндексе и обратная семантика в Google. Простая проверка SerpApi по нашим исходным вопросам не раскрывает все запросы конкурента.

ПровайдерПокрытие и APIОриентир стоимости / ограниченияРоль в MIRVIX
Keys.soБазы Яндекса в Москве, Петербурге и других городах России; отдельные базы Google, набор регионов фиксирован документацией. REST API есть в Professional/Corporate.Профессиональный: 9 300 ₽/мес на проверенной тарифной странице; лимит API и методы зависят от подписки.Основной кандидат для Яндекса и РФ.
DataForSEO LabsRanked Keywords, Domain Intersection, Competitors Domain для Google; страна и язык по location code. Это не аналогичная база обратных ключей Яндекса.Для большинства Labs Google методов от $0.012 за задачу + $0.00012 за элемент, по странице цен; уточнить endpoint, лимит и данные.Основной кандидат для Google.
TopvisorКонкурентный анализ Google/Яндекс и регионов, отдельные инструменты и API. Наличие нужного метода автоматического обратного экспорта проверять до покупки.Поштучная оплата операций, состав тарифа и API уточнять.Резерв/пилот по региональной выдаче.

Выбор: начать с ограниченного пилота Keys.so для Яндекса; DataForSEO подключить для Google после проверки выдачи по тем же доменам. Не покупать два тарифа до пилота на 3–5 конкурентах и оценки глубины региональных данных.

Источники: Keys.so цены, Keys.so API, DataForSEO цены, DataForSEO Ranked Keywords, Topvisor справка. Тарифы и покрытие уточняйте непосредственно перед оплатой.

6. Проверка перед коммерческим запуском

  1. Подтвердите вход двух разных клиентов: клиент А не видит организацию/проекты/отчёты Б.
  2. Поставьте бесплатный аудит, закройте вкладку, вернитесь и проверьте историю.
  3. В Preview вручную обработайте шаг. Запланированный worker включается на production только после одобрения.
  4. Не выставляйте глобальный paid switch, пока не установлены реальные тарифы, ограничения и кредиты.
  5. После активации лимитов запустите один тест каждого провайдера и проверьте ответ, web grounding, ссылки и затраты.
  6. Не объединяйте PR №38 с production до всех проверок.
