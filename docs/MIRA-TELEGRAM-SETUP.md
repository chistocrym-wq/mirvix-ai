# MIRA — подключение Telegram к заявкам MIRVIX AI

Серверные функции `mira-brief.mjs` и `mira-submit.mjs` работают в Netlify. Не публикуйте токен Telegram в GitHub, URL сайта, HTML, переписке или скриншотах.

## Telegram — два приватных параметра

1. В Telegram откройте официального `@BotFather`, отправьте `/newbot` и создайте отдельного бота для заявок MIRVIX AI. Бот должен иметь уникальное имя пользователя, оканчивающееся на `bot`.
2. Откройте нового бота в своём Telegram-аккаунте и нажмите **Start** (`/start`). Бот не может сам начать личную переписку.
3. Узнайте числовой `chat.id` **этой переписки** из ответа Telegram Bot API `getUpdates`, получаемого с токеном вашего бота после `/start`. Запрашивайте эти данные только самостоятельно и никому не пересылайте токен. Телефонный номер не является `chat_id`.
4. В своём существующем проекте Netlify в **Project configuration → Environment variables** создайте переменные **MIRA_TELEGRAM_BOT_TOKEN** (секрет BotFather) и **MIRA_TELEGRAM_CHAT_ID** (числовой chat.id). Доступ — Functions, если интерфейс предлагает scope. Сохраните и redeploy.
5. Через Netlify Deploy Preview проверьте передачу тестовой заявки и получение полного текста в Telegram. Без переменных сервер честно отвечает 503, а MIRA предлагает письмо.

Telegram получает сформулированную задачу, исходное сообщение, указанный клиентом канал связи и контакт только после явно отмеченного согласия на передачу обращения. При публикации требуется проверить соответствие требованиям о персональных данных, включая трансграничную передачу, применимую к обработке ваших клиентов.

## ИИ-перефразирование

Функция `/api/mira-brief` использует `OPENAI_API_KEY` и `OPENAI_BASE_URL` из серверного окружения Netlify (например, при поддержке AI Gateway), а не из кода браузера. Без них MIRA сохраняет исходные слова клиента полностью и честно сообщает о недоступности автоматического оформления; не выдаёт их за перефразировку моделью.

## Проверка и публикация

До подтверждения работы Telegram и готовности политики обработки данных изменения держим в отдельном PR. После этого можно объединить изменения в `main`. `MIRA_TELEGRAM_*` никогда не включать в репозиторий или frontend.
