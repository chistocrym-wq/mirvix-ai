# MIRVIX GEO Publisher — первая версия

Изолированный модуль: `/publisher/`. Ветка `feature/geo-publisher-mvp`. В production не включать без проверки.

## Доступ

1. Откройте `/cabinet/` в том же домене Deploy Preview и войдите как сотрудник.
2. Для входа нужны существующие переменные Netlify `MIRVIX_AUDIT_PASSWORD` (12+ символов) и `MIRVIX_CABINET_SESSION_SECRET` (32+ символов).
3. Partner-роль не имеет доступа к Publisher.
4. Все запросы к API выполняются из браузера той же origin с HttpOnly-сессией.

## Поиск

Установите в настройках Netlify Site configuration → Environment variables:

- `MIRVIX_SERPAPI_KEY`: API-ключ сервиса SerpApi, с доступом к Google и Yandex (проверить тариф/квоты до работы). Альтернатива: `SERPAPI_KEY`.
- Не публикуйте ключ в GitHub, HTML, Netlify build logs или URL сайта.

В одном запуске до 10 запросов и до 2 поисковых систем. Один шаг = один вызов SerpApi. До 20 органических URL на шаг, регион Google задаётся текстом location + gl, регион Яндекса — числом lr (2 — СПб, 213 — Москва). Реальный состав ответа зависит от API; при неработающем API ошибки отображаются, данные не генерируются.

Механика: старт → поочерёдный сбор запросов → дедуп по доменам → сохранение результатов и индекса запусков в Netlify Blobs → оценка с известными/неизвестными критериями → статусы → экспорт.

Если вкладка закрылась после старта, откройте историю и нажмите «Продолжить поиск». Повторяются только незавершённые шаги. Позиции фиксируются только по реальной выдаче.

## Анализ и проверка

- «Проверить профиль сайта» использует существующий защищённый HTML-аудитор MIRVIX.
- «Найти контакты и условия редакции» проверяет типовые публичные страницы внешнего сайта с безопасным DNS-pinning и ограничениями по размеру/времени. Найденный текст — **кандидат на подтверждение**, а не доказательство возможности платной публикации.
- Сотрудник вручную проверяет условия, затем вводит URL-источник, условия, цену (если известна), контакты, качество, соответствие региону.
- Подтверждённые условия требуют URL-источник и описание. Пустые сведения остаются пустыми. Нет вымышленных цен и контактов.
- Общая база хранит универсальные сведения о доменах; SEO-позиции, рейтинг, ТЗ и статусы ведутся отдельно по каждому запуску.

## Рейтинг

Веса из ТЗ: релевантность 30%, видимость SEO 20%, возможность публикации 20%, качество 15%, регион/аудитория 10%, доступность и стоимость 5%.

Для непроверенных факторов показываются диапазон возможного результата и охват подтверждённых критериев. Балл скрыт, пока проверено меньше 70% веса критериев; неизвестный факт не превращается в ноль или выдуманную оценку.

## Экспорт

`XLSX` и `CSV`: домен, выдача, кластер, запросы, тип площадки, релевантность, статус публикации, условия, контакты, ссылки-источники, цена, приоритет, тема и ТЗ, статусы, комментарии, дата публикации и URL.

## Границы MVP

В рамках первой версии не реализованы:

- автоматические выводы о разрешении публикации без проверки редактором;
- отправка писем/заявок редакциям;
- генерация готового тела статьи;
- сбор AI-цитирований из ChatGPT, Gemini, Perplexity;
- статистическая оценка причинного эффекта конкретной публикации;
- полноценное multitenant-разделение нескольких компаний-клиентов с отдельными пользователями (доступ ограничен staff).

Эти пункты относятся к последующим итерациям или отдельному расширению ТЗ. Прежде чем продавать функцию, проведите пилот на 5–10 сайтах: ≥85% тематической релевантности по оценке специалистов, 100% подтверждённых условий с источниками, ≥99% дедупликации, ≥80% ТЗ без существенных правок.

## Проверка

- PR CI: `MIRVIX GEO Publisher MVP` запускает `node --check` и `node --test tests/geo-publisher.test.mjs`.
- Проверить вход/выход, настройки ключа, получение реальных позиций для 1 кластера, ошибки лимита API, просмотр после перезагрузки, сохранение статусов и ссылок, загрузку XLSX.
- Слияние в `main` и production-deploy — только после подтверждения владельца.
