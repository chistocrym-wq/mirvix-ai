# MIRVIX GEO Tools — ограниченный просмотр и платные отчёты

## Реализованный первый инструмент

- **Сравнение товаров конкурентов**: посетитель даёт ссылки на свой товар и 1–5 карточек других магазинов.
- **Ознакомление**: одна неполная проверка для подписанного анонимного браузера; сервер ограничивает до 1 конкурента, скрывает подробные характеристики, расчёт разницы и CSV.
- **Полный отчёт**: 490 ₽ за 1 конкурента, 990 ₽ за 2–3, 1 990 ₽ за 4–5. Это тестовые цены, не опубликованное коммерческое обязательство на другие инструменты.
- Покупка открывается только после явного включения оплаты, настройки живого магазина ЮKassa, фискального чека и серверного секрета. Покупка подтверждается запросом к API ЮKassa; URL оплаты нельзя подменить с клиента.
- Один платёж разрешает одну полную проверку **ровно указанных при оплате URL**. Все решения о доступе выполняются только сервером.
- При отсутствии подтверждённой оплаты полный отчёт не отдается.
- Идентификатор браузера хранится в подписанном cookie с HttpOnly, Secure, SameSite. Очистка cookie и смена браузера позволяют получить новое ознакомление: без аккаунтов/подтверждения телефона невозможно гарантировать одно ознакомление *на человека*.

## Netlify → Environment variables

| Переменная | Назначение |
| --- | --- |
| `MIRVIX_TOOLS_SESSION_SECRET` | Случайный секрет от 32 символов; при отсутствии использует текущий `MIRVIX_CABINET_SESSION_SECRET` (если уже настроен) |
| `MIRVIX_TOOLS_PAYMENTS_ENABLED` | Только значение `1` включает оплату |
| `YOOKASSA_SHOP_ID` | ID реального магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | Секретный API-ключ реального магазина |
| `MIRVIX_TOOLS_VAT_CODE` | Согласованный с бухгалтером код ставки НДС в чеке ЮKassa |

Переменные должны быть доступны Netlify Functions, после изменения нужен новый production deploy. **Не публиковать секреты в GitHub, HTML, отчётах или чате.** Если переменных нет, сайт показывает клиенту «оплата подключается» и не создаёт платежи.

Критично проверить требования 54-ФЗ и наличие корректного процесса фискализации в договоре ЮKassa прежде чем включать реальные платежи. В API передаётся email покупателя для чека и одна позиция с суммой, валютой RUB и кодом НДС.

## Перед запуском продаж

1. Настроить реальные платёжные реквизиты и тестовый магазин. Проверить редирект, возврат, чек, статус `pending` / `succeeded`.
2. Проверить в браузере одну бесплатную попытку, повторную блокировку, отказ от оплаты, возврат после подтверждения, невозможность повторно использовать покупку или менять URL.
3. Испытать 15–20 реальных товарных карточек из разных магазинов. Не обещать поиск или фото там, где HTML закрыт, а цены живут в JavaScript.
4. Подключить поддержку оплаты/возвратов, обработку ошибок и юридические условия предоставления цифровой услуги.
5. Решить проблему повторного доступа на уровне подтверждённых клиентских аккаунтов; cookie не гарантирует «один на человека».
6. Рассчитать себестоимость, поддерживать лимиты запросов и регулярную очистку устаревших записей Netlify Blobs.

## Остальные инструменты

- Технический аудит — остаётся базовой бесплатной проверкой, как существовал до монетизации.
- Проверка присутствия ИИ, генератор вопросов, конкурентные домены — существующий **доступ сотрудников**, публичная ограниченная демоверсия и платежи пока не выпущены.
- GEO Rank, история, генератор статей, мониторинг цен — в разработке, **не продавать** до реализации.
- Расширение «1 ознакомление на каждый инструмент» требует отдельных публичных API с такими же серверными квотами и гарантированным результатом.

Идея «все инструменты по отдельности за оплату» зафиксирована как целевая архитектура, а не уже реализованная продажа неготовых функций.
