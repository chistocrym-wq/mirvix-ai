# MIRVIX GEO Check — 7 провайдеров / 30–100 вопросов

Тестовый интерфейс: `/check/`, секция «Проверить упоминания компании в нейросетях».

## Подключение (Netlify → Environment variables)

Ключи хранятся **только на сервере**. Не включать их в HTML, репозиторий, скриншоты и клиентские отчёты.

| Название в отчёте | Серверный ключ | Режим | Примечание |
| --- | --- | --- | --- |
| ChatGPT | `OPENAI_API_KEY` | веб-поиск в Responses API | `gpt-6-luna`; ключ также нужен для автоматической генерации вопросов |
| Gemini | `GEMINI_API_KEY` | Google Search grounding | `gemini-3.8-flash`; тестовый вызов обязателен |
| DeepSeek | `DEEPSEEK_API_KEY` | Web Search Responses API | `deepseek-v4-pro`; отдельные тарифы поиска |
| Grok | `XAI_API_KEY` | Web Search Responses API | `grok-4.7`; отдельные тарифы поиска |
| GigaChat | `GIGACHAT_AUTH_KEY` | ответы модели **без подтверждённого веб-поиска** | Base64 authorization key, OAuth, `GIGACHAT_SCOPE` по доступу (B2B по умолчанию) |
| Алиса AI | `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Alice AI LLM + Yandex Web Search | Yandex AI Studio. **Это API-модель, не выдача приложения «Алиса»**. |
| Perplexity | `PERPLEXITY_API_KEY` | Agent API · `fast` preset, веб-поиск | Получить ключ в [Perplexity API Console](https://console.perplexity.ai/), включить оплату API. |

Perplexity входит в общий список из семи выбираемых моделей. В ноябре 2026 года использует рекомендованный Perplexity Agent API (`/v1/agent`) вместо устаревшего Sonar Chat Completions.

Сессия сотрудника: `MIRVIX_AUDIT_PASSWORD` и `MIRVIX_CABINET_SESSION_SECRET`, вход через `/cabinet/`. Генератор `geo-prompts` и платные вызовы `direct-geo` принимают только запросы сотрудника той же HTTPS-origin.

## Принцип измерения

1. Провести технический аудит: взять название, title и description со страницы. При блокировке главной страницы вручную указать категорию.
2. Войти как сотрудник, открыть `/check/`, проверить подключения.
3. Выбрать 30/50/70/100 **различных, небрендовых** покупательских вопросов. OpenAI или Gemini генерирует их партиями; проверяйте релевантность до запуска.
4. Выбрать подключённые системы. Стоимость зависит от тарифов, модель может выполнить несколько платных поисковых вызовов на один вопрос.
5. Каждая пара (вопрос × API) — отдельный платный вызов; после одного подтверждения выполняется вся оставшаяся матрица последовательно в открытой вкладке; есть кнопка остановки.
6. Успешные ответы, прямые цитаты, упоминания бренда и URL, ошибки и версия модели отображаются отдельно. Не объединять отсутствующий/ошибочный ответ с ответом без упоминания.
7. Сохранить полную выборку JSON и таблицу CSV. Данные существуют только в открытой вкладке, серверная история и фоновый worker пока не реализованы.

**Не считать модельные ответы GigaChat с выключенным веб-поиском полноценной текущей поисковой выдачей.** Наличие ключа не означает успешную проверку: проверять первыми пробными запросами. API-ответы не равны персонализированной выдаче сайтов и приложений ChatGPT, Gemini, Алисы и т.д.

## Риски перед Production

- Нужны оплаченные аккаунты и права для каждого API, по одному реальному запросу для smoke test.
- Проверить себестоимость 30/50/70/100 вопросов × число систем: 100 × 7 = **700 обращений**, не считая генерации вопросов и внутренних search tool вызовов.
- Запуск остаётся ручным, в открытой вкладке; длительные проверки лучше переносить в фоновые Netlify Background Functions + очередь и сохранять в БД с расходными лимитами.
- Установить rate limiting по сотруднику и серверную квоту до широкой продажи.
- При смене категории/списка вопросов/моделей очищать план или начинать новую выборку, не смешивать разные методики.
